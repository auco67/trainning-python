### 第一章

`git init`の実行でローカル上にリポジトリを新規作成することができ、その後に管理するファイルを配置する。リポジトリ内で特に管理したくないファイルは`.gitignore`ファイル内で設定させる。`git add`で管理するファイルを追加し、`git commit`で確定させる。`git status`で状況を確認することができる。

<a id="01"></a>

#### ローカルリポジトリの作成

```
git init
```

コンソール上でリポジトリを確認する

```
ls -force
```

.gitフォルダが自動生成されいる

```
    Directory: C:\Users\<user_name>\Documents\github\trainning-python

Mode                 LastWriteTime         Length Name
----                 -------------         ------ ----
d--h-          2025/05/15    15:39                .git
```

<a id="02"></a>

#### 管理対象外とする設定（.gitignore）

.gitignore ファイルを作成しリポジトリから対象外としたいディレクトリまたはファイルを記述する

.gitignore

```
data/
dist/
docs/
Excel/
input/
jsons/
key/
log/
output/
pdf/
templates/
venv/
web/
.env
```

<a id="03"></a>

#### ステージング（add）

```
git add ファイル名
```

<a id="04"></a>

#### コミット(commit)

```
git commit -m メッセージ
```

<a id="05"></a>

#### ステータス(status)

```
git status
```

<a id="2"></a>

### 第二章

ブランチは、`master(main)`を複製させたもの。ブランチは複数作成することができ、開発する人毎、機能毎に作成し、`master(main)`のデータを担保しつつ、`master(main)`のデータを複製したブランチで変更や機能追加の内容を加えることができる。特に、ブランチの変更がエラーを生まない状況が確認できれば、そのブランチの内容を`master(main)`にマージすることにより、`master(main)`を最新のデータとすることができる。

<a id="06"></a>

#### ブランチの作成

- ブランチを作成する場合
    ```
    git branch <branch_nam>
    ```

- ブランチを作成し、かつ、作成したブランチに切り替える場合
    ```
    git checkout -b <branch_name>
    ```

<a id="07"></a>

#### ブランチの切り替え

    ```
    bit switch <branch_name>
    ```


<a id="3"></a>

### 第三章

ローカル上にあるリポジトリの内容をクラウド上のリモートリポジトリにデータ更新することができる。これにより、ネット環境があればどこからでもアクセスして、誰でもリポジトリを更新することができる。

<a id="08"></a>

#### リモートレポジトリの作成

```
git remote add origin https://github.com/<username>/<repository_name>.git
```

<a id="09"></a>

#### リモートレポジトリにプッシュ(push)

ローカルリポジトリの内容をリモートレポジトリに更新する

```
git push origin <branch name>
```

<a id="10"></a>

#### リモートリポジトリからプル(pull)

リモートリポジトリから最新版をローカルリポジトリに取得する

```
git pull
```

<a id="4"></a>

### 第四章

複数のブランチにより、リモートリポジトリに`push`後は、`pull request`で`master(main)`にマージ申請を行う。その後、特に内容に問題がなければ、`master(main)`に`merge`で統合させる。

もしマージした際にコンフリクトが発生した場合は、コンフリクトが発生したという内容がファイル内容に記述されるので、手動でファイルを修正する。

<a id="5"></a>

### 第五章

既存のリモートリポジトリをローカル上に複製する。ローカル上に複製させることにより、その状態から変更や機能追加を行うことができる。

<a id="11"></a>

#### リモートリポジトリのクローン(clone)

既存のリモートリポジトリをローカルに複製する

```
git clone https://github.com/<username>/<repository_name>.git
```
